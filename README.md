# Садоход R8 — единые чаты и предпросмотр iPhone

Полное содержимое R7 сохранено. Версия R8 обновляет четыре чата и Flutter-предпросмотр на компьютере, **не меняя серверную схему и Docker Volumes**.

- Чаты поддержки и сотрудничества покупателя и продавца используют одни виджеты шапки, сообщений, поля ввода и нижних отступов из `shared/flutter_core/lib/chat_widgets.dart`.
- Composer автоматически растёт с одной строки до пяти и затем прокручивается, не накрывая кнопку отправки.
- Время и отметки доставки встроены в поток текста, поэтому не перекрывают конец сообщения.
- Перед таббаром теперь предусмотрен отдельный отступ 17 px, при клавиатуре — 8 px.
- Seller support: рисунок #CCB7B4, seller cooperation: #D6DEE4, фон #F0EFEB.
- Оба приложения используют один `SadohodDevicePreviewShell` (iPhone 16 Pro 402 × 874 в десктопном Chrome). На настоящем телефоне дополнительная рамка не рисуется.

Важно: сообщения, отправка вложений, таймеры обновления переписки и Telegram API оставлены прежними. Нет изменений в базе и миграциях.

**Установка:** распакуйте в отдельную папку; при работающем Docker и после резервного копирования запустите `ОБНОВИТЬ САДОХОД.bat`. Старую папку не удаляйте, пока не проверите оба приложения.

**Ручная проверка:** откройте по очереди четыре чата, введите сообщение на 1 / 3 / 6+ строк, проверьте движение курсора, перенос времени, видимость кнопок и промежуток перед таббаром при открытой клавиатуре; проверьте фотографию и PDF. При запуске Flutter Web на десктопе обе программы должны показывать рамку iPhone, на узком экране — без неё.

**Ограничение проверки:** в среде подготовки нет Docker, Flutter и GUI Chrome с работающей сборкой. Статические и серверные проверки проведены отдельно; реальная сборка и визуальная проверка 4 экранов должны быть выполнены на Windows.

# Садоход · локальная сборка для Windows

Текущая поставка: **0.8.4+26 / 2026-11-16-R8**. Источник версии —
`RELEASE.json`; расположение подписей и порядок выпуска описаны в
[docs/VERSIONS_R5.md](docs/VERSIONS_R5.md).

Распакуйте ZIP в отдельную папку. Изменения этого патча перечислены в [docs/R7_CHAT_AND_PG_PATCH.md](docs/R7_CHAT_AND_PG_PATCH.md). Нужны Docker Desktop (Linux containers, Compose v2), Google Chrome и Flutter с Dart 3.10 или новее, доступный через PATH. Для первой сборки нужен интернет. Приложения открываются в Chrome в режиме разработки.

| Ваша ситуация | Что открыть |
|---|---|
| На этом компьютере ещё нет данных Садохода | **ПЕРВЫЙ ЗАПУСК.bat** |
| Уже есть база, фотографии и настройки проекта | **ОБНОВИТЬ САДОХОД.bat** |
| Проверить доступность сервера и приложений | **ПРОВЕРИТЬ САДОХОД.bat** |

Покупатель — http://localhost:55114, продавец — http://localhost:55115, сервер — http://localhost:8000/health. Закрывайте прежние окна запуска Flutter перед повторным запуском. После успешной первой установки для повторного запуска используйте кнопку обновления.

### Первый запуск

Сценарий проверяет наличие существующей установки, создаёт локальный пароль PostgreSQL, собирает сервер и открывает два клиента. В новой базе включены демонстрационные данные. При прерывании повторите первый запуск из той же папки. Пока установка не завершена, сохраняйте файлы .env и .first-install.pending. Для работы почты и Telegram нужны собственные настройки сервисов.

### Обновление

В R4 подключены миграции Alembic. Перед запуском нового API они проверяются
на восстановленной копии базы с контролем сохранности существующих записей.
При несовместимой структуре обновление останавливается. Подробности и границы
проверки этой сборки: [docs/MIGRATIONS_R4.md](docs/MIGRATIONS_R4.md).

Используется Compose-проект sadohod_mvp_v0_2 с тремя томами sadohod_pg, sadohod_uploads и sadohod_admin_state (имена в Docker начинаются с имени проекта). Папка со старым проектом и место для дампа, копии фото и временной базы должны быть доступны. Закончите редактирование данных перед запуском.

Сценарий использует .env в новой папке или в каталоге, указанном в метке Docker Compose прежней базы. Для стандартной установки доступен перенос настроек БД, SMTP и Telegram из контейнеров. Если прежние контейнеры удалены, вручную скопируйте .env именно этой установки в новую папку. При индивидуальных параметрах сети или внешних интеграциях перенесите исходный .env.

После сборки нового образа скрипт останавливает прежний API, делает pg_dump и копирует его на компьютер. Проверка читает сохранённый файл с диска, восстанавливает его во временную базу в том же PostgreSQL и сверяет количество продавцов, товаров, павильонов и записей о фото. Затем скрипт копирует файлы фотографий и состояние из томов, смонтированных для чтения. Копии остаются в backups. Эта папка содержит приватные данные. При ошибке резервирования скрипт пытается запустить прежний API, если он работал.

После обновления откройте известный вам товар в кабинете продавца и проверьте фото и павильон в приложении покупателя. При ошибке запуска нового сервера сохраните папку backups, старую папку проекта и Docker-тома для восстановления. Автоматического отката после замены API нет.

### Состав поставки

Исходники покупателя и продавца, общий Flutter-код, FastAPI, Docker, демоданные, инструменты и исходные материалы. Браузерные клиенты собираются Flutter. Старый скомпилированный маршрут /mobile-demo исключён. Нейросетевой поиск использует отдельную конфигурацию docker-compose.ml.yml.

Для сборки ZIP из исходников нужна Python 3.9+ и команда `python tools/package_release.py путь-к-новому.zip`. Файлы берутся из tools/release_files.txt. При добавлении исходников обновите список. Скрипт формирует docs/FILE_MANIFEST_SHA256.json внутри ZIP и проверяет каждый файл после записи. Сам манифест исключён из собственного списка хэшей.

### Фотопоиск и смена почты

Лимит фотопоиска — 20 запросов с IP за календарную минуту и два одновременных запроса на процесс сервера. Размер фотографии до 8 МиБ. На загрузку отводится 30 секунд. Для PostgreSQL ранжирование векторов ограничено 2,5 секунды на SQL-запрос и выдаёт до 200 кандидатов. При большом числе ракурсов одного товара число различных товаров в ответе может быть меньше запрошенного. SQLite предназначен для небольших подборок до 2048 подходящих изображений. Для более крупных нужен PostgreSQL.

В HTTPS-конфигурации Caddy использует 172.29.246.2 в сети 172.29.246.0/28. Если эта подсеть занята в Docker или VPN, выберите свободную и согласуйте IP Caddy и FORWARDED_ALLOW_IPS в docker-compose.https.yml.

При смене почты подтверждение одноразовое, допускается пять попыток на код и 60 подтверждений с IP в час. Ответ на запрос письма одинаков для свободного и занятого адреса. Оба варианта отправляют код на указанный ящик. Существующий владелец сохраняет свой адрес.

### Изолированные серверные тесты

Кнопка **ПРОВЕРИТЬ СЕРВЕРНЫЕ ТЕСТЫ.bat** запускает набор на SQLite, затем отдельно проверяет PostgreSQL 17 с pgvector и одновременное подтверждение почты. Нужен Docker Desktop и интернет для первой сборки. Используются отдельный Compose-проект и временная БД в памяти. Код завершения 0 означает успешный прогон. Кнопка не подключается к базе приложения.


### ВОРОТА — проверка перед выпуском

Дважды нажмите **ВОРОТА.bat** в корне проекта. Скрипт по очереди запускает
проверку согласованности версий, изолированные серверные тесты на SQLite
и PostgreSQL 17 в Docker, а затем `flutter pub get`, `flutter analyze`,
`flutter test` и `flutter build web` для **seller_app** и **buyer_app**.
Понадобятся Docker Desktop, Python и Flutter в PATH; первое выполнение
может потребовать загрузки образов и зависимостей. Рабочие PostgreSQL-тома
не используются в тестовой конфигурации `tools/compose.qa.yml`.

- **Код 0** — все этапы прошли, ни один не пропущен.
- **Код 1** — есть ошибки, релиз ещё не готов.
- **Код 2** — ошибок нет, но проверки пропущены: это не зелёный прогон.

Результаты сохраняются в `gate-logs/ГГГГММДД-ЧЧММСС/`,
итог — `summary.txt`, подробности — в отдельных `.log`. Папка игнорируется Git
и **не включается** в ZIP. Флаг `-Quick` пропускает сборку Flutter Web,
что приводит к коду 2, даже когда остальные шаги проходят.

**Важно:** пока нет подтверждённого прогона этих ворот на Windows PowerShell 5.1
с Docker и Flutter. До получения кода 0 и визуальной проверки экранов
не считать сборку полностью протестированной.
