# R7 — заявки на павильоны

Основа — R6, включающий последний R5_FIXED_SELLER и защиту автоответов.
Версия поставки: 0.8.4+24 / 2026-11-16-R7.

## Исправлено

- При повторном входе продавец с заявкой и без подтверждённых павильонов
  попадает в существующий экран «Мои магазины». Заявка остаётся видимой
  со статусом «На проверке» или «Отклонён».
- Подтверждённые первоначальные заявки больше не дублируют павильоны в списке.
- Открытие списка/статуса, переход через таббар и возвращение в приложение
  обновляют данные. На экране заявки отображается актуальный результат
  проверки; после подтверждения используется настоящий идентификатор павильона.
- Отклонённая первоначальная заявка редактируется через PUT /merchant/applications/{id}.
  Дополнительный павильон — через PUT /merchant/pavilions/requests/{id}.
  Сохраняется прежний id, статус становится pending, причина отклонения очищается.
- Повтор идентичного POST или PUT для уже ожидающей заявки возвращает её id.
  Отличающийся запрос во время проверки отклоняется понятным сообщением.
- Запись на PostgreSQL сериализована блокировкой владельца. Модерация и
  повторная отправка используют согласованный порядок блокировок.
- Чужие заявки недоступны для редактирования; подтверждённую заявку повторно
  отправить нельзя. Неподтверждённый павильон нельзя привязать к товару.
- Перед исправлением очищаются поля прежнего адреса. Код вида Б-2В-82
  раскладывается по полям; нестандартный старый код сохраняется целиком,
  чтобы не потерять часть адреса при повторной отправке.
- После отправки кнопка возврата ведёт к списку, без возврата в уже отправленную форму.

Использованы существующие экраны и компоненты. Новые макеты и новые
дизайнерские состояния не добавлялись. Исправление product_actions.dart
из R5_FIXED_SELLER, автосохранение форм и защита автоответов R6 сохранены.
Новых миграций базы в R7 нет.

## Проверки

В текущей среде: **123 серверных теста прошли, 4 PostgreSQL-теста пропущены**.
Проверены полный цикл заявки, повторная отправка, отсутствие дублей в
последовательных повторах, доступ только владельцу, защита неподтверждённого
павильона и доступ к нему после одобрения. Проверены синхронизация версий
и сценарии подписей админки. Изменённый Dart-код прошёл синтаксический разбор.

Добавлены Flutter widget-тесты на 390/402 px: повторный вход, переход к заявке,
обновление после подтверждения, ограничения добавления товара и исправление
первой/дополнительной заявки. Их можно запустить из seller_app:

```sh
flutter test test/startup_test.dart test/pavilion_flow_test.dart
```

Эти Flutter-тесты здесь **не выполнялись**. Flutter analyze, release-сборка,
визуальная проверка Chrome, Windows и Docker не выполнены. Ранее автоматическая
проверка отклонила запуск Flutter из-за обращения к адресу cloud-метаданных;
обход этой блокировки не использовался. Синтаксический разбор не подтверждает
проверку типов, расположение элементов и реальную работу интерфейса.

Конкурентные POST/PUT включены в test_postgres_onboarding.py и второй этап
«ПРОВЕРИТЬ СЕРВЕРНЫЕ ТЕСТЫ.bat». Они требуют отдельной PostgreSQL QA-базы.

## Проверка на установке

1. Отправить первую заявку, закрыть приложение, открыть снова: видна та же
   заявка, а не предложение впервые добавить магазин.
2. Отклонить её в админке с причиной. Открыть заявку, исправить номер,
   отправить повторно: id не меняется, заявка снова на проверке.
3. Подтвердить заявку. Вернуться в приложение: павильон доступен для товара
   и не появляется в списке второй раз как отдельная старая заявка.
4. Повторить отклонение и исправление для дополнительного павильона.
5. На 390 и 402 px проверить экраны, клавиатуру, возврат и нажатия по макетам V3.

Вне этого патча остаются: необязательная цена, контакты профиля, свободный
ручной адрес без номера, загрузка фото входа, статусы и действия с товарами.
Сценарий «Адреса нет в справочнике?» этим патчем не закрыт.
