## Публикация и обновление
После утверждения сохранить каждую **окончательную** версию отдельно от каталога drafts.
На новом VPS, с изолированным каталогом `./legal_published` (он игнорируется Git),
команда выполняется из корня репозитория:

```sh
python3 tools/publish_legal.py --source /secure/approved/privacy.md \
  --slug privacy --version 2026-12-01 --effective-date 2026-12-01 \
  --reviewed-by "ФИО утвердившего" --destination ./legal_published
```

Команда отвергает все известные редакционные пометки/заглушки, пустое утверждение
и источники непосредственно из `docs/legal/drafts`; сохраняет SHA256 и прежнюю
редакцию в `legal_published/archive/<slug>/`.
**Сам флаг --reviewed-by не заменяет юридического согласования и не проверяет полномочия лица.**
Доступ к каталогу публикации должен быть только у доверенного оператора VPS.

После публикации и запуска HTTPS следующие адреса будут работать без авторизации:

- `https://<ПОДТВЕРЖДЁННЫЙ_API_DOMAIN>/legal/privacy`
- `/legal/buyer-terms`, `/legal/seller-terms`
- `/legal/content-rules`, `/legal/data-deletion`

Android/iOS используют тот же источник через `/api/v1/legal/{slug}`.
Незаполненные документы API не публикует; вместо них возвращает ошибку.
Не ставить ссылку в App Store/Google Play, пока реальный HTTPS не отдаёт HTTP 200,
полный текст, правильного оператора и правильную редакцию с мобильной сети.

Обновления текстов не требуют сборки приложений, но изменение условий или цели обработки
может требовать уведомления и/или отдельного согласия пользователя.

## Apple App Privacy и Google Play Data safety — данные для декларации

| Данные | Реальное использование | Требует проверки перед декларацией |
|---|---|---|
| Email | OTP вход, смена почты | хранение/срок/передача SMTP |
| Имя аккаунта | профиль, отзывы | отображается ли публично |
| Контакты продавца | магазин/павильон | являются ли персональными и публичными |
| Фото | товар, аватар, отзывы, вложения | EXIF/метаданные, права, ML, сроки |
| Переписка | поддержка и сотрудничество | Telegram и внешние получатели |
| Жалобы/модерация | безопасность | получатели и сроки |
| ID аккаунта/сессии | вход/антиспам | хранение, связность с пользователем |
| IP/телеметрия | серверная защита | фактические логи/SDK |
| Камера/галерея | добавление изображений | доступ к выбранным фото, разрешения ОС |
| Местоположение | **не подтверждён доступ к GPS** | не отмечать геолокацию без проверки SDK |

Не утверждать «данные не собираются». Для обоих приложений заполнять декларации
с учётом фактического API, SDK и получателей. Чужие фотографии/персональные данные
в карточках требуют проверки оснований публикации и удаления.

## Согласия и дизайн
Сейчас **не реализован отдельный утверждённый Figma-экран для согласий**.
Нельзя делать автопроставленные чекбоксы, считать получение OTP согласием
или автоматически писать в журнал БД запись о согласии. Если конкретная обработка
законно основана на согласии, до её включения утвердить отдельный текст, состояние
интерфейса и серверное доказательство (версия, время, субъект, действие, отзыв).
Иные правовые основания не нужно выдавать за согласие.

## Удаление аккаунта
Покупатель: кнопка удаления есть, сервер удаляет связанные данные при отсутствии
принадлежащего магазина/действующей заявки.
Продавец: пока обращение в поддержку, требуется довести **реальный процесс**
удаления магазина, товаров, прав управления и хранимых ПД с сообщением о результате.
Google Play дополнительно требует публичный web resource для запроса удаления.
Документ `data-deletion` не эквивалентен работающему процессу обработки запроса.
