# R5 — согласованные версии

Единая версия поставки: **0.8.4+22**, идентификатор **2026-11-15-R5**.
Номер 22 больше прежних номеров сборок Flutter в pubspec.yaml.

Источник — `RELEASE.json`. Из него `tools/sync_version.py` формирует константы
Python, Dart и JavaScript и обновляет pubspec.yaml обоих клиентов и общей
Flutter-библиотеки. Упаковщик останавливается при несовпадении этих файлов.

| Компонент | Где посмотреть |
|---|---|
| API | `/health`, документация OpenAPI, `/api/v1/admin/status` после авторизации |
| Обе админки | Подпись с отдельными версиями интерфейса и API |
| Покупатель | «О приложении», заголовок вкладки браузера |
| Продавец | Внизу личного кабинета, заголовок вкладки браузера |
| Windows | Окно запуска клиента; «ПРОВЕРИТЬ САДОХОД.bat» сравнивает файлы и API |

Версия приложения встроена в его код; она не подменяется ответом API.
Если интерфейс админки и сервер отличаются, отображается предупреждение.
Диагностика Windows проверяет номер API и версию файлов текущей папки;
открытый порт Flutter сам по себе не подтверждает версию запущенного клиента.

В API сохранено поле `version` (теперь `0.8.4`), добавлены `build_number`,
`full_version`, `release_id`, `label`. Поле `server_patch` оставлено как
устаревший псевдоним `build_number`, чтобы не убирать его из ответа.

Для следующего выпуска изменить RELEASE.json и выполнить из корня:

```sh
python tools/sync_version.py
python tools/sync_version.py --check
python tools/package_release.py путь-к-архиву.zip
```

Номер сборки увеличивать при каждом выпуске. Нельзя вручную переопределять
`--build-name` / `--build-number`: это создаст расхождение с встроенной подписью.
После обновления нужны пересборка API и перезапуск обоих Flutter-клиентов.
Обычный «ОБНОВИТЬ САДОХОД.bat» выполняет эти действия после своих проверок.

Проверено:
- 112 серверных тестов прошли; 3 PostgreSQL-теста пропущены.
- 2 проверки синхронизации версий, включая отказ при устаревшем клиенте.
- 3 JavaScript-сценария: одинаковые версии, старый сервер, недоступный сервер.
- Синтаксис пяти изменённых Dart-файлов проверен парсером.
- В profile_features.dart исправлена лишняя закрывающая скобка, существовавшая
  в R4 в разметке сообщения чата покупателя.

Flutter analyze, Flutter release-сборка, визуальная проверка экранов,
Windows и Docker в этом прогоне не выполнялись. Проверка синтаксиса Dart
не заменяет проверку типов, сборку и проверку интерфейса. №13 остаётся открытым.
Правки №6 и №8 сохранены; ограничения проверки миграций описаны в MIGRATIONS_R4.md.
