# Проверка точности модерации OpenCLIP

Система модерации **не распознаёт достоверно вещества или оружие** — это
вероятностная сортировка: `review` означает «отправить человеку», `allow`
означает «пропустить автоматическую проверку». Сходство OpenCLIP не является
вероятностью. Пороги `product_screening.py` **пока не откалиброваны**.

## Как сформировать набор

1. Подготовить **реальные** изображения с разрешением на обработку и
   независимо проверить их вручную, без опоры на ответ модели.
2. Не загружать фотографии из пользовательских аккаунтов в репозиторий,
   GitHub Actions или публичные сервисы. Хранить выборку отдельно и
   ограничивать доступ. Удалять/обезличивать EXIF и персональные данные.
3. В той же закрытой папке записать CSV `labels.csv`:

   ```csv
   image_path,expected,group
   ```

   Для каждой строки `image_path` — локальное имя файла или относительный
   путь от CSV. `expected` = `review` (требует ручной проверки) или `allow`
   (допустим). `group` — группа, определённая человеком; включить
   запрещённые предметы, подозрительные упаковки, обычную одежду,
   игрушки, порошковые продукты бытового назначения, иллюстрации.
   **Не считать все изображения одного типа заведомо запрещёнными.**
4. По возможности собирать достаточно примеров разных освещений,
   ракурсов, продавцов и фонов; не допускать дубликатов между
   проверочным и обучающим набором. Согласовать с модераторами критерии
   «требует ручной проверки» и фиксировать неоднозначные разметки.

## Запуск

На доверенном рабочем компьютере с зависимостями `requirements-ml.txt`
и загруженной моделью OpenCLIP:

```sh
python tools/evaluate_moderation_photos.py \
  --manifest /secure/moderation/labels.csv \
  --output /secure/moderation/report.json
```

Скрипт локально вычисляет реальные эмбеддинги той же модели и применяет
**текущие** пороги без их изменения. На экран выводит только агрегаты:
`true_review`, `missed_review`, `false_review`, `correct_allow`,
`review_recall`, `false_negative_rate`, `false_positive_rate`,
`review_precision` и количество ошибок ML, ушедших на ручную проверку.

Обязательно отдельно разобрать **пропущенные** опасные товары (FN) и
**ложно задержанные** допустимые (FP). Пороговые значения изменять только
после ревью реальных материалов и повторного независимого теста.
Результаты на искусственных оценках сходства в CI не свидетельствуют
о качестве реального распознавания. Без выборки **процентов точности нет**.

**Важно:** этот инструмент оценивает только визуальную проверку одного
изображения. Полный процесс учитывает дополнительно названия, описания,
несколько фотографий, статус продавца, ручную модерацию и жалобы.
Для полного релизного решения отдельно измерить весь товарный pipeline,
нагрузку на очередь и задержку до решения модератора.
