# R8 · коррекция поля ввода и метаданных сообщений (0.8.4+27)

На основании скриншотов buyer/seller от 16.11.2026 уточнён **один общий компонент** для четырёх чатов.

- Поле ввода: высота однострочного состояния 44 px; вертикальные отступы заданы единожды через `InputDecoration` (12 px), `StrutStyle` гарантирует одинаковую высоту строки для плейсхолдера и вводимого текста; рост от 1 до 5 строк и внутренняя прокрутка после 5 строк сохранены.
- Короткое сообщение: время и подтверждение **отправки** стоят справа в той же строке, с устойчивым промежутком.
- Многострочное сообщение: время выделено в отдельную строку справа снизу с отступом 4 px. Больше нет `WidgetSpan` внутри текста и зависимости ширины от жёсткой прибавки 83 px.
- Ширина: рассчитывается из ширины фактического текста и контейнера, с общим верхним пределом 291 px и одинаковыми внутренними отступами. Вложения используют независимую ширину 232 px, не зависящую от пустого текста.
- Значок отправки: только у исходящих сообщений один check для сохранённого сообщения; двойное прочтение возможно лишь при `read == true`. Текущее API `read` не отдаёт, поэтому фальшивый статус «прочитано» не показывается. Входящие сообщения без галочек.
- Паттерны, таббары, серверные маршруты, авторизация, история сообщений, отправка фото и файлов не изменялись.

## Тестирование

`tools/test_r8_chat_contract.py` проверяет статический контракт. `seller_app/test/chat_layout_r8_test.dart` содержит widget-тесты на размеры поля, ввод, многострочное поле и статус исходящих/входящих сообщений. Перед использованием на Windows выполнить `ВОРОТА.bat` (если установлены gate-скрипты) или `flutter analyze`, `flutter test`, `flutter build web` по обоим Flutter-проектам и проверить четыре чата в Chrome. Эти проверки не заменяются статическим контрактом.

## Известное ограничение

Сервер пока не передаёт состояние фактического прочтения сообщения. Для двух галочек потребуется отдельный статус от сервера и логика подтверждения чтения; рисовать их всегда неправильно.
