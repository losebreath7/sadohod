## Начало каждого нового задания

1. Найти репозиторий, проверить актуальный SHA `develop`, SHA своей ветки и все открытые PR.
2. Прочитать утверждённые ограничения проекта и найти соответствующий экран Figma.
3. Проверить пересечения с чужими изменениями в `server/`, `shared/`, навигации или общих виджетах.
4. До команды «старт» не менять исходники, ZIP, код или интерфейс; сначала описать план и возможные риски.
5. После «старт» изменять только согласованную область и свою ветку. Не делать merge в `develop` / `main` самостоятельно, пока владелец не подтвердил соответствующий PR.

## Обязательная запись о выполненной задаче

В описании Pull Request написать:
- Что изменено и какие пути затронуты.
- Из какой ветки начата работа и на какой SHA она основана.
- Какие автоматические проверки прошли **на текущем SHA**.
- Как выполнялась визуальная проверка в Chrome/iPhone 16 Pro и что фактически наблюдалось. Если недоступно — прямо написать «не проверено визуально».
- Есть ли изменения общего API, схемы БД, `shared/`, миграций и обратной совместимости.
- Что требуется от владельца перед merge.

## Важные ограничения

- Чаты **не синхронизируют собственные сообщения**: общий источник фактов — GitHub, коммиты, PR, Issues и согласованные Figma-макеты.
- `git pull` обновляет файлы клона, но не перезапускает локальный Flutter и Docker. Для просмотра изменений понадобится обновить код и перезапустить соответствующий клиент.
- Не удалять рабочую PostgreSQL, Docker Volumes, файлы пользователей, резервные копии, `.env`.
- Рабочие ветки изолируют изменения, но **не гарантируют** отсутствие конфликтов при последующем слиянии.
- Текущая приватная `main` не защищена правилами GitHub на стороне сервера из-за ограничений тарифа. Не воспринимать описанные запреты как технически включённую защиту.

Работаем только в назначенной ветке, не переписываем другие ветки. До команды «старт» — анализ и согласование. UI строго по существующим макетам Figma; проверяй визуально перед merge. PR только в `develop`; в `main` — только подтверждённый релиз.
